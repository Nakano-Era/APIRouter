# Docker Work 沙箱与可选 Claude Code

Work 默认使用项目自带的工具调用引擎，在一次性 Docker 容器中读写文件、执行命令、使用技能、分派子任务。不需要安装 Claude Code，也不要求 Claude 模型。支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 三种接口；所选模型及上游必须支持相应的工具调用格式。

界面只会提供从工作区读取到的真实文件下载，不会把模型输出的文件说明当作已经生成的文件。普通 Chat 继续直接调用 API，不启动工作容器。Claude Code 保留为可选渠道运行方式。

## 一键启用

先完成 [VPS 部署](DEPLOY-VPS.md)，在项目目录执行：

```bash
sudo bash deploy/work-enable.sh
```

也可以在首次部署时执行 `sudo bash deploy.sh --with-work`。脚本构建通用沙箱镜像、启动执行器，向现有 `.env` 写入执行器凭据及 `COMPOSE_FILE=compose.yaml:compose.work.yaml`。之后常规 `docker compose up -d --build --wait` 会保留 Work 配置。升级沙箱代码时再次运行启用脚本，以重建工作镜像。

首次构建需要访问 Docker、Debian 和 Python 软件源；默认安装过程不下载 Claude Code。执行器端口不需要公开到公网，`.env` 不应提交到 GitHub。

1. 在后台添加 API 地址、密钥和正确协议，运行方式选择“直接 API”。
2. 同步模型后先测试普通回答，再确认上游支持工具调用。
3. 在后台 Work 页确认沙箱可用，调整资源上限。
4. 在聊天页选择 Work，运行“创建一个 SVG 并保存到 output”的小任务，下载实际文件。

模型同步或普通回答成功，不能证明上游支持工具调用。上游不支持时会保留实际错误；不会将普通回答伪装成执行成功。沙箱不可用时会明确提示管理员启用 Docker。

## 可选 Claude Code

只在确实需要该引擎时运行：

```bash
sudo bash deploy/work-enable.sh --with-claude-code
```

此命令另行构建 `claude-worker` 镜像并持久化设置 `WORK_CLAUDE_IMAGE`。将对应渠道设为 Anthropic Messages 协议与 Claude Code 运行方式；地址、模型和认证方式须由提供商明确支持。后续启用脚本会继续更新已安装的可选镜像。CLI 固定版本由 `runner/Dockerfile` 的 `CLAUDE_CODE_VERSION` 定义。

Claude Code 的 Chat 调用禁用工具，Work 调用开放 Agent、Skill、Read、Write、Edit、Bash、Glob、Grep，并可按次开启 WebSearch。兼容性取决于该提供商对 Claude Code 请求的支持。项目没有集成 cc-switch。

## 输出中断与继续

输出超时、连接中断、主动停止或应用重启后，可以对原回答选择“继续生成”。已有文本会保留，新内容接在原回答末尾。模型获得先前对话与已输出内容，避免从头重新生成；这是应用层恢复，不是恢复上游已断开的连接。未送达服务器的 token、模型内部状态无法取回，模型仍可能出现内容重复或变化。

模型明确标记的思考、推理摘要与 Responses commentary 过程会单独显示在默认收起的“思考与过程”中，不再拼进正文；复制和导出只取正文。原生 Work 与可选 Claude Code 均支持，过程文本在中断和重启后也保留。协议要求的签名思考块仍保存在隔离的工具检查点中，加密数据和签名不会展示。没有任何标记、已经与正文混成普通文字的上游内容无法自动可靠拆分。

默认原生 Work 引擎会将工具调用前后的执行记录加密保存到数据库，与用户、对话及回答绑定。在工具检查点发送前，先保存 `output/` 中已有的实际文件。继续时恢复该回答的工具记录和工作文件，已完成的工具调用不会自动重放；中断时状态不确定的调用会作为未确认结果交给模型处理，避免盲目重复操作。恢复需要原上游模型 ID 和协议保持一致。每份执行记录最多 32 MB；对话删除时对应记录也会删除。

新的任务容器只恢复已保存的输出文件，未保存的临时文件、正在运行的进程和容器内存不能恢复。宿主机硬故障发生在两次检查点之间时，只能保留最近成功保存的状态。Claude Code 延续使用可见对话和已保存文件，不恢复它内部的隐藏 CLI 会话或工具记录。

## 资源与任务边界

默认每个任务：768 MB 内存、1 CPU、128 个进程、20 轮模型调用、600 秒时限；最多同时两个工作任务。后台范围为 512–4096 MB、0.25–4 CPU、1–80 轮、30–1800 秒、1–4 个并发沙箱。应用默认每用户不同对话同时 4 个任务、全站 10 个，同一对话串行；沙箱并发上限另外生效。

原生引擎通过轮数、输出 token、任务时限与 Docker 资源限制控制用量，**不声称能按美元准确止损**：第三方模型价格无法由通用工具引擎可靠推断。后台的美元预算只传给可选 Claude Code，仍依赖 CLI 对价格的认识；实际费用以提供商账单为准。

上下文与单次输出上限使用该模型在后台的配置，可同步上游容量信息或手动设置。系统不会把历史静默截断到 300 条；未知容量不猜测，交给上游判断。消息请求（含 JSON 包装）、历史传输和任务提示词的安全上限为 32 MB；模型容量配置接受最多 1000 万上下文 token、100 万最大输出 token，这些只是配置上界，不表示任意模型实际支持。触及传输上限会明确报错，不悄悄丢弃历史。站点每次请求的输出预算与模型能力上限是不同设置。

AnyRouter 的 Responses 可使用自动 / 标准 / Codex 请求兼容配置，原生 Work 与 Chat 共用适配；这不需要安装 Codex CLI，也不保证专属 Key 的调用权限。Codex 兼容请求不发送 `max_output_tokens`，由上游默认值决定单次输出；标准接口仍执行选定的输出 token 限制。

Work 建议至少 2 核 4 GB VPS；多个并发任务或大上下文需要更多内存。建议不是压力测试结果。镜像预装 Node.js、Python 3、Pillow、python-docx、openpyxl、ReportLab、python-pptx、Git、ripgrep 和 Bash。需要额外依赖时由管理员修改镜像并重建。任务没有任意外网权限，不能临时联网安装软件，也不能挂载宿主机目录。

每个输出文件最多 10 MB，一次最多 30 个、合计 30 MB，每位用户最多保存 500 个工作文件、合计 200 MB。只导出 `output/` 下的普通文件；隐藏文件、符号链接、硬链接与越界路径不导出。HTML 和 SVG 强制下载。输出及执行记录保存在数据库中，会随数据库备份保存。当前没有后台无人值守队列或浏览器桌面控制。

## 技能、搜索与隔离

管理员可以粘贴 `SKILL.md`，或从公网 HTTPS 原始 Markdown 地址导入；成员可选择与下载管理员提供的技能。每份最大 64 KB，最多保存 32 份，每次最多使用 10 份。导入的是 Markdown 指令，不自动安装仓库、插件、MCP、hooks 或附属脚本。需要额外脚本资源时由管理员预装到工作镜像。

原生引擎通过 Anthropic 或 Responses 的上游搜索工具提供网络搜索；成功与否取决于提供商与模型。Chat Completions 没有统一搜索工具，因此该协议下不承诺搜索能力。Claude Code 使用它的内置 WebSearch。项目不提供任意网页抓取或联网 shell，也不会伪造搜索结果。

工作容器以非 root 运行，只读根文件系统，独立内网 Docker 网络及限额临时文件系统。真实 API Key 留在应用和执行器网关，工作进程仅持有本任务的短期凭据。网关只允许所选协议的请求路径、所选模型、已启用工具及输出预算，校验公网地址并固定 DNS，不跟随重定向。Responses 使用无远端持久会话模式。

只有 `work-runner` 管理容器持有 Docker socket，应用与任务容器都不持有。该管理容器属于高权限组件，应及时更新。容器共享宿主机内核，不能视为独立虚拟机。执行器重启会清理遗留的任务容器与网络。

## 验证与排错

```bash
docker compose ps
docker compose logs --tail=100 work-runner
node --test tests/work.test.mjs tests/native-agent.test.mjs
```

管理员可在请求日志中查看经过凭据遮蔽的原始上游错误。测试覆盖沙箱参数、各协议网关、凭据隔离、文件导出、所有权、执行记录及中断恢复。开发环境没有运行 Docker Engine，因此真实镜像构建和具体第三方渠道仍应在目标 VPS 用小任务验证。
