# 套餐、申请开通与 Stripe 订阅

用户在聊天页右上角点击“升级套餐”，或在左下角账户菜单中打开“套餐与订阅”。套餐名称、价格、币种、按月或按年、每日请求额度、模型范围及开通方式，都由管理员设置。初始安装没有虚构的付费套餐或默认收款账户。

## 创建套餐

1. 管理员打开“管理工作空间 → 套餐与支付”。
2. 添加套餐，填写名称、说明、价格及币种，选择月付或年付。
3. 设置每日请求额度、允许使用的统一模型名。模型权限对应统一模型路由，同一路由中的备用渠道自动沿用权限。
4. 选择“申请开通”和/或“Stripe”，保存并上架。未上架的套餐不向用户提供新购买。

免费套餐每日额度在“工作空间”中设置；免费用户的模型范围在套餐支付设置中配置。模型名单留空表示允许全部已启用模型，不能把留空当作禁止访问。管理员账号可使用所有已启用模型，仍受每日额度限制。

“成员与邀请”中的个人额度若填写数值，会覆盖套餐额度；清空后保存可恢复套餐默认额度。0 表示不允许生成。额度按 UTC 日期计算，失败或停止的对话请求也计入；渠道内部重试不会重复扣本站请求次数，但上游可能分别收费。

同一成员卡片中的“各模型版本使用额度”提供更细的每日/每月限制，每个模型的每个版本独立计数。例如“ChatGPT 6 Astra · 高智商版”每天 10 次、“普通版”每天 100 次，两者不共用额度；同一版本绑定的多个渠道共用该版本额度。留空表示不限此项，0 禁止调用。它与成员/套餐总额度同时生效，不覆盖总额度。版本额度按台北时间 UTC+8 的自然日、自然月重置；新生成、继续、重新生成各记一次，内部渠道重试不额外计次。

## 指定用户的专属模型路由

在“成员与邀请”找到用户，展开“专属模型路由”，选择用户看到的模型及版本，再选择实际执行的目标模型及版本。例如 `Opus 5.5 · 高智商版 → GPT 6 · 默认版本`。保存后仅对该用户生效，可单独停用或删除规则。

用户的模型选择器、对话和消息仍保留所选源模型名称；源模型的套餐权限与版本额度仍生效，请求只记入源版本一次，不额外占用目标版本额度。后台路由日志记录实际执行目标与渠道。目标的思考强度可单独配置，默认自动，不受用户选择的源模型思考强度影响。

首选方案下方可以不断添加备用方案，并用上移、下移排列顺序；每项独立选择模型、版本与思考强度。备用方案没有固定数量上限，仍受接口请求体大小限制；同一模型、版本和思考强度的重复组合会被拒绝。每个方案内部只在该模型版本的渠道间重试，失败、超时、空输出或上游明确标记未完成时，再顺次进入下一方案。原模型只有被显式加入备用列表才会执行，不递归套用其他用户规则。

输出中断时保留已有文字，用已有内容要求下一方案接续，不重新创建一条回答；无法保证模型绝不重复或改写，也不会根据正常结束的文字猜测任务是否完整。全部方案失败后，用户仍可手动继续。主动停止不触发备用方案。原生 Work 可携带已保存的文件和安全检查点交接，不能可靠确认已执行操作时停止并保留结果，避免自动重放；可选 Claude Code 已执行操作后不自动交接。

每个方案中继承站点设置的渠道共用全局总尝试预算，默认 6、可设 1–100。上游模型可以设置独立额外重试次数 0–100，留空继承全局 0–3（默认 1）；独立次数不被站点默认预算或本轮自身触发的冷却截断；次数只影响临时错误，鉴权或参数错误不会强制同渠道重试。一个用户请求在所有方案间只扣一次所选源版本和账号额度，但每次上游调用仍可能计费。用户有任务运行时不能修改其专属路由。

这些规则保存在站点数据库中；“配置迁移”或完整数据备份均可迁移，单独的 API 渠道备份不包含用户专属路由。配置迁移不带走已使用的额度，完整搬家请使用完整数据备份。

“导出聊天记录”可由管理员选择全部或指定用户下载聊天 ZIP，支持 JSON 与 Markdown，包含已归档聊天和单独保存的思考过程；附件与任务文件仅包含元数据，不包括文件内容、服务密钥或密码。完整站点恢复使用部署文档中的数据目录备份。

## 特殊分组邀请

1. 在“成员与邀请 → 特殊邀请分组”点击“新增分组”，填写名称。
2. 选择已有套餐（含未上架套餐）、指定免费版，或不指定套餐而沿用站点免费配置。指定套餐时可选择从注册日起一个套餐周期、长期有效或统一截止时间；免费版一个周期为一个月。邀请有效期与套餐期限分别计算。
3. 添加专属路由：选择用户可见的模型版本、后台首选执行模型和思考强度，并按需要添加和排序备用方案。路由的权限、额度与接续规则与个人专属路由一致。
4. 保存分组，在“创建邀请”的分组选项中选择它；可绑定邮箱并选择 1 天、7 天或 30 天的链接有效期。复制生成的链接交给受邀者。
5. 受邀者注册新账号后，套餐权益和专属路由在同一次操作中生效。每个链接只能使用一次，已有账号不能用邀请重复领取权益。已注册成员可在其“用户套餐”和“专属模型路由”中单独调整。

创建链接时保存当时的套餐快照与路由，之后修改分组或套餐不会悄悄更改已发出链接的权益；模型改名会同步有效引用。停用分组期间，未使用的链接不能注册；重新启用后，仍在有效期内的链接可继续使用。删除分组后未使用的链接失效。已注册成员的套餐和路由不会随分组修改、停用或删除而联动变更。

赠送套餐作为管理员指定权益保存，不收费、不创建 Stripe 订阅。按周期赠送从注册成功时开始，自定截止时间不随注册时间延长。邀请到期、统一权益截止时间已过、分组已删除或创建邀请的管理员已失效时，需要创建新邀请。临时渠道离线不阻止领取有效的邀请，但实际执行仍需要可用模型。

分组模板随“配置迁移”导出；已发出的邀请链接不随配置包迁移。目标服务器导入后重新创建并分发链接，现有成员的已获权益与路由按用户配置迁移。

## 管理员直接更改用户套餐

1. 在“成员与邀请”找到指定用户，展开“用户套餐”。当前有效套餐、额度、来源及原订阅会分别显示。
2. 选择免费版或任意已有套餐，包括未上架的套餐。
3. 选择从现在起一个月/一年（随套餐周期）、长期有效，或自定截止时间。免费版的“一个周期”为一个月。
4. 可填写仅管理员可见的调整说明，点击“保存套餐”立即生效。

管理员指定的权益独立保存在原订阅上方，来源标记为管理员指定。指定免费版会实际使用保存时免费版的额度与模型范围，而不是继承原付费套餐；已经给该用户单独设置的每日上限仍优先。更改套餐不会清零今日、本月或各模型版本的已用次数。

指定期限结束，或点击“恢复原订阅”后，按当时仍有效的原人工/Stripe 订阅恢复权益；原订阅已到期则使用当前免费方案。恢复不延长原订阅的时间。管理员可查看调整记录，包括操作人、时间、套餐、截止时间和说明；模型改名会同步当前指定套餐的模型范围，保留审计记录当时的值。

此功能只调整站内权限，不收费、不退款，也不会取消或更改 Stripe 付款订阅。原 Stripe 续费继续更新底层订阅，但不会覆盖正在生效的管理员指定套餐；客户门户仍可使用。指定权益生效期间禁止新增支付或人工开通，已有待审核申请也不能通过，以免开通后看不到相应权益；先恢复原订阅即可按原规则处理。

套餐权限在后续请求中即时按新权益校验；已开始执行的任务不因套餐调整重新计次。本站仅调整套餐与请求权限，不提供 Stripe 中途换价、按比例结算功能。

## 站内公告

在“管理工作空间 → 公告管理”创建内容，保存为草稿或立即发布。标题最多 120 字符、正文最多 20000 字符，支持 Markdown 和数学公式，并提供预览；HTML 不执行。下架后内容保留为草稿，普通用户不可见。

已发布公告在登录后的工作空间显示，关闭或点击“知道了”会将当前版本标记已读。记录按用户保存在数据库，同一账号不同设备刷新、聚焦或周期检查后同步。编辑已发布内容或重新发布会增加版本，之前已读的成员再次看到更新；正在看旧版本的客户端不能误标新版本已读。两位管理员同时编辑时，后保存的旧版本会提示先刷新，避免覆盖另一人的修改。

## 使用申请开通

无需配置 Stripe，即可只开放“申请开通”：

1. 用户选择套餐并提交说明。
2. 管理员在申请列表中查看用户、申请时的套餐价格与权益、说明。
3. 管理员选择同意或拒绝，可填写审核说明。普通用户不能审核申请，管理员也不能审核自己的申请。
4. 同意后立即生效，按套餐月/年周期计算到期时间。相同人工套餐续期开通会从现有到期时间延长；换成人工新套餐会立即替换当前权益，不自动计算剩余价值。

申请本身不扣款，也不代表已收款。是否已付款或满足开通条件，由管理员核实。每位用户同时只允许一个待审核申请，重复审核不会重复延长会员。

只有一位有效管理员时，该管理员不能为自己提交人工申请，避免出现无人能够审核的申请。管理员可直接在成员卡片调整自身套餐与额度，并已拥有全部已启用模型的使用权限；普通受邀成员仍按正常申请流程开通。

## 配置 Stripe

先完成 VPS 域名与 HTTPS 部署。Stripe 托管支付页负责收款，本站不接收银行卡号；订阅使用 Stripe Checkout 的 recurring subscription 流程，参见 [Stripe Checkout 订阅文档](https://docs.stripe.com/payments/checkout/build-subscriptions)。

1. 在 Stripe 账户中取得 Secret Key，将它填写到后台“套餐与支付”的 Stripe 配置中。
2. 在 Stripe Workbench 中创建本站的 Webhook，地址为：

   ```text
   https://你的域名/api/billing/webhook
   ```

3. 选择以下事件：

   ```text
   checkout.session.completed
   checkout.session.async_payment_succeeded
   customer.subscription.created
   customer.subscription.updated
   customer.subscription.deleted
   invoice.paid
   invoice.payment_failed
   ```

4. 复制这个 Webhook 的 `whsec_...` 签名密钥，填写到本站后台，保存并启用 Stripe。Webhook 注册和签名密钥说明见 [Stripe Webhook 文档](https://docs.stripe.com/webhooks)。
5. 在 Stripe 中启用客户门户，允许取消订阅、修改付款方式和查看账单。当前版本不处理门户切换套餐产生的权益映射或按比例计费，请不要在门户开放切换产品/价格。入口设置参见 [Stripe 客户门户文档](https://docs.stripe.com/customer-management/activate-no-code-customer-portal)。
6. 为需要在线支付的套餐勾选 Stripe 并上架。用户支付后返回本站，后台收到并验证支付通知后才开通；如果暂未开通，可刷新订阅状态，并查看 Stripe 的 Webhook 投递记录。

Secret Key 与 Webhook Secret 加密保存，保存后不会向浏览器返回完整值。留空提交表示保留原密钥。备份仍需包含完整数据库和 `master.key`。

建议在独立测试站与 Stripe 测试模式完成验收，然后在正式站配置正式 Key 与对应的正式 Webhook。测试与正式环境的支付对象、密钥和签名密钥不能混用；站点已创建 Stripe 订单后，会拒绝直接切换测试/正式密钥模式。同一站点不提供跨 Stripe 收款账号迁移功能。

## 续费、取消和到期

- Stripe 套餐按配置的周期自动续费。用户可通过“管理 Stripe 订阅”进入本人对应的客户门户。
- 取消自动续费不会删除已经确认的当前周期权益；到期后恢复免费套餐。
- 支付成功回跳地址不能证明已付款。本站验证 Webhook 签名，并向 Stripe 查询当前订阅、已付账单及订单归属；重复或乱序通知不会按到达次数重复增加会员时间。
- 已有有效会员或未结束的 Stripe 订阅时，不允许再次创建独立订阅，避免重复付费。离开或取消支付后，订单会保留约 31 分钟；可返回同一套餐的原支付页继续，改用人工申请则需等待订单过期并由服务器确认。网络异常或支付结果未确认时可能需要更久，本站不会单凭经过了多久就把可能已付款的订单清除。
- 修改套餐价格与权益用于后续新购买或新申请；已有会员和待审核申请保留开通/申请时的套餐快照。修改价格不会直接改变旧 Stripe 订阅的扣款金额。
- 当前版本未提供站内退款、优惠券、税费计算、套餐中途自动换档与按比例计费。退款等事项在 Stripe 后台处理；本站没有将退款自动转换为会员权益回收的规则。

## 验证范围

本项目使用本地模拟 Stripe 客户端及签名通知测试权限、审批、额度、管理员套餐覆盖/到期/恢复、并发付款通知、重复通知和支付归属，不会发起真实扣款；公告权限、更新版本和用户间已读隔离另有接口测试。真实 Docker/VPS 部署与联网搜索仍需在目标环境验收；真实收款需要管理员用自己的 Stripe 账号、域名与 Webhook 完成测试模式验收后再启用正式模式。
