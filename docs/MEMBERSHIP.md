# 套餐、申请开通与 Stripe 订阅

用户在聊天页右上角点击“升级套餐”，或在左下角账户菜单中打开“套餐与订阅”。套餐名称、价格、币种、按月或按年、每日请求额度、模型范围及开通方式，都由管理员设置。初始安装没有虚构的付费套餐或默认收款账户。

## 创建套餐

1. 管理员打开“管理工作空间 → 套餐与支付”。
2. 添加套餐，填写名称、说明、价格及币种，选择月付或年付。
3. 设置每日请求额度、允许使用的统一模型名。模型权限对应统一模型路由，同一路由中的备用渠道自动沿用权限。
4. 选择“申请开通”和/或“Stripe”，保存并上架。未上架的套餐不向用户提供新购买。

免费套餐每日额度在“工作空间”中设置；免费用户的模型范围在套餐支付设置中配置。模型名单留空表示允许全部已启用模型，不能把留空当作禁止访问。管理员账号可使用所有已启用模型，仍受每日额度限制。

“成员与邀请”中的个人额度若填写数值，会覆盖套餐额度；清空后保存可恢复套餐默认额度。0 表示不允许生成。额度按 UTC 日期计算，失败或停止的对话请求也计入；渠道内部重试不会重复扣本站请求次数，但上游可能分别收费。

同一成员卡片中的“各模型版本使用额度”提供更细的每日/每月限制，每个模型的每个版本独立计数。例如“ChatGPT 6 Astra · 高智商版”每天 10 次、“普通版”每天 100 次，两者不共用额度；同一版本绑定的多个渠道共用该版本额度。留空表示不限此项，0 禁止调用。它与成员/套餐总额度同时生效，不覆盖总额度。版本额度按台北时间 UTC+8 的自然日、自然月重置；新生成、继续、重新生成各记一次，内部渠道重试不额外计次。

## 指定用户的专属模型路由

在“成员与邀请”找到用户，展开“专属模型路由”，选择用户看到的模型及版本，再选择实际执行的目标模型及版本。例如 `Opus 5.5 · 高智商版 → GPT 6 · 默认版本`。保存后仅对该用户生效，可单独停用或删除规则。

用户的模型选择器、对话和消息仍保留所选源模型名称；源模型的套餐权限与版本额度仍生效，请求只记入源版本一次，不额外占用目标版本额度。后台路由日志记录实际执行目标与渠道。目标的思考强度可单独配置，默认自动，不受用户选择的源模型思考强度影响。

每条规则只执行一次映射，不递归套用其他规则。失败切换仅在目标模型的同一版本内进行；目标不可用时返回错误，不会自动切回源模型。用户有任务运行时不能修改其映射。已有 Work 检查点仍要求实际目标模型与协议兼容，不兼容时会阻止续写并保留原内容。

这些规则保存在站点数据库中；迁移需使用完整数据备份，单独的 API 渠道备份不包含用户专属路由。

“导出所有用户聊天”可由管理员下载全站聊天 ZIP，支持 JSON 与 Markdown，包含已归档聊天和单独保存的思考过程；附件与任务文件仅包含元数据，不包括文件内容、服务密钥或密码。完整站点恢复使用部署文档中的数据目录备份。

## 使用申请开通

无需配置 Stripe，即可只开放“申请开通”：

1. 用户选择套餐并提交说明。
2. 管理员在申请列表中查看用户、申请时的套餐价格与权益、说明。
3. 管理员选择同意或拒绝，可填写审核说明。普通用户不能审核申请，管理员也不能审核自己的申请。
4. 同意后立即生效，按套餐月/年周期计算到期时间。相同人工套餐续期开通会从现有到期时间延长；换成人工新套餐会立即替换当前权益，不自动计算剩余价值。

申请本身不扣款，也不代表已收款。是否已付款或满足开通条件，由管理员核实。每位用户同时只允许一个待审核申请，重复审核不会重复延长会员。

只有一位有效管理员时，该管理员不能为自己提交人工申请，避免出现无人能够审核的申请。管理员可直接在后台调整自身额度，并已拥有全部已启用模型的使用权限；普通受邀成员仍按正常申请流程开通。

## 配置 Stripe

先完成 VPS 域名与 HTTPS 部署。Stripe 托管支付页负责收款，本站不接收银行卡号；订阅使用 Stripe Checkout 的 recurring subscription 流程，参见 [Stripe Checkout 订阅文档](https://docs.stripe.com/payments/checkout/build-subscriptions)。

1. 在 Stripe 账户中取得 Secret Key，将它填写到后台“套餐与支付”的 Stripe 配置中。
2. 在 Stripe Workbench 中创建本站的 Webhook，地址为：

   ```text
   https://你的域名/api/billing/webhook
   ```

3. 选择以下事件：

   ```text
   checkout.session.completed
   checkout.session.async_payment_succeeded
   customer.subscription.created
   customer.subscription.updated
   customer.subscription.deleted
   invoice.paid
   invoice.payment_failed
   ```

4. 复制这个 Webhook 的 `whsec_...` 签名密钥，填写到本站后台，保存并启用 Stripe。Webhook 注册和签名密钥说明见 [Stripe Webhook 文档](https://docs.stripe.com/webhooks)。
5. 在 Stripe 中启用客户门户，允许取消订阅、修改付款方式和查看账单。当前版本不处理门户切换套餐产生的权益映射或按比例计费，请不要在门户开放切换产品/价格。入口设置参见 [Stripe 客户门户文档](https://docs.stripe.com/customer-management/activate-no-code-customer-portal)。
6. 为需要在线支付的套餐勾选 Stripe 并上架。用户支付后返回本站，后台收到并验证支付通知后才开通；如果暂未开通，可刷新订阅状态，并查看 Stripe 的 Webhook 投递记录。

Secret Key 与 Webhook Secret 加密保存，保存后不会向浏览器返回完整值。留空提交表示保留原密钥。备份仍需包含完整数据库和 `master.key`。

建议在独立测试站与 Stripe 测试模式完成验收，然后在正式站配置正式 Key 与对应的正式 Webhook。测试与正式环境的支付对象、密钥和签名密钥不能混用；站点已创建 Stripe 订单后，会拒绝直接切换测试/正式密钥模式。同一站点不提供跨 Stripe 收款账号迁移功能。

## 续费、取消和到期

- Stripe 套餐按配置的周期自动续费。用户可通过“管理 Stripe 订阅”进入本人对应的客户门户。
- 取消自动续费不会删除已经确认的当前周期权益；到期后恢复免费套餐。
- 支付成功回跳地址不能证明已付款。本站验证 Webhook 签名，并向 Stripe 查询当前订阅、已付账单及订单归属；重复或乱序通知不会按到达次数重复增加会员时间。
- 已有有效会员或未结束的 Stripe 订阅时，不允许再次创建独立订阅，避免重复付费。离开或取消支付后，订单会保留约 31 分钟；可返回同一套餐的原支付页继续，改用人工申请则需等待订单过期并由服务器确认。网络异常或支付结果未确认时可能需要更久，本站不会单凭经过了多久就把可能已付款的订单清除。
- 修改套餐价格与权益用于后续新购买或新申请；已有会员和待审核申请保留开通/申请时的套餐快照。修改价格不会直接改变旧 Stripe 订阅的扣款金额。
- 当前版本未提供站内退款、优惠券、税费计算、套餐中途自动换档与按比例计费。退款等事项在 Stripe 后台处理；本站没有将退款自动转换为会员权益回收的规则。

## 验证范围

本项目使用本地模拟 Stripe 客户端及签名通知测试权限、审批、额度、重复通知和支付归属，不会发起真实扣款。真实收款需要管理员用自己的 Stripe 账号、域名与 Webhook 完成测试模式验收后再启用正式模式。
