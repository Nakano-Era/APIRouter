# 跨服务器配置迁移

配置迁移可以把当前站点的渠道、模型、用户、限额、路由、套餐和其他后台设置导入另一台服务器。后台生成独立密码保护的加密 JSON 文件，目标站点先预览，再合并保存；不需要复制源站主密钥。

如需连同聊天记录、附件、已经使用的额度和 Stripe 订阅关联完整搬家，请使用 [完整数据备份与恢复](DEPLOY-VPS.md#备份与恢复)。配置迁移不包含这些运行数据。

## 包含哪些内容

| 分类 | 迁移内容 |
| --- | --- |
| 站点 | 站点名称、系统提示词、默认模型、每日次数、输出上限、渠道尝试与重试设置 |
| 渠道与模型 | 地址、完整上游密钥、协议、认证方式、运行方式、优先级、开关、失败保护、模型容量、思考强度、识图与模型重试设置 |
| 模型目录 | 用户看到的模型名称、版本、渠道绑定、空目录草稿、模型旧标识关联 |
| 用户 | 账号、姓名、密码哈希、角色与停用状态；个人总额度、各模型版本日/月限额、专属路由与有序备用方案 |
| 特殊邀请 | 邀请分组名称、开关、赠送套餐、期限与完整专属路由模板；不包含已经发出的邀请链接 |
| 会员 | 套餐定义、免费模型范围、支付设置；当前有效权益及其原到期时间 |
| Work | 后台资源设置、搜索配置、已保存的技能内容 |
| 其他 | 渠道余额查询适配方式、公告草稿及发布内容、对外 API 密钥的授权范围与校验哈希 |

以下内容不会导入：聊天与消息、附件与任务产物、Work 检查点、已用额度与请求历史、登录会话与登录设备、邀请链接、公告已读、余额缓存、模型测试/冷却状态、错误日志、支付订单/客户/订阅/通知记录、历史审计。

`.env`、域名、HTTPS 证书、`PUBLIC_ORIGIN`、`MASTER_KEY`、Work 执行器地址与认证凭据等部署参数仍使用目标服务器的配置。配置包也不会替你安装 Docker、启动执行器或下载搜索服务镜像。

## 操作步骤

1. 在目标服务器部署相同版本的 APIRouter，创建并登录目标管理员。若目标已有数据，先制作完整备份。
2. 在源站“管理工作空间 → 配置迁移”导出。填写当前管理员登录密码，以及单独设置的 12–256 位备份密码，下载加密 JSON。
3. 在目标站进入同一页面，选择 JSON 文件，填写目标管理员的登录密码和这份备份的密码，生成导入预览。
4. 检查各项新增、更新、保留数量和冲突说明，尤其是同邮箱用户、当前套餐、支付设置及对外 API 密钥。勾选“我已核对上述明细，确认将源配置合并到本机”，再点击“导入配置”。
5. 导入后检查默认模型、真实模型调用、用户登录、套餐与限额。启用 Work 时，在新服务器检查执行器及搜索连接；更换域名时重新检查 Stripe Webhook 地址和签名密钥。

预览有效期为 10 分钟，只对生成预览的管理员和当前服务进程有效。重启服务、预览过期或目标配置发生变化后，需要重新预览。生成、模型测试、同步或支付等相关操作尚在进行时，导入会提示稍后重试，防止用旧状态覆盖正在完成的操作。

已删除模型留下的默认选择会被清空，不会阻止其他配置导入；旧配置包在预览中会提示这项处理。

导入是一次数据库事务，验证失败不会保留部分配置。它会合并来源配置并保留目标独有的记录，不提供自动撤销；需要回退时使用导入前的完整备份。

## 合并规则与密码

首次导入以明确的业务标识匹配记录：用户按邮箱；渠道按名称、地址、协议和运行方式；渠道模型按所属渠道与原始模型 ID；模型目录、版本、套餐、技能、邀请分组按名称；对外 API 密钥按校验哈希。公告使用来源关联，首次导入可匹配唯一同标题公告。同名存在多个候选而无法确定时会拒绝，需先处理歧义再导入。

同一来源后续导入会保留来源记录与目标记录的关联，避免源记录改名后重复创建。仍应阅读每次预览，导入不是两个站点之间的持续同步，也不会删除目标独有的配置。

- **新用户**：导入原密码哈希，可以用原密码在新站登录；源站已停用的账号仍保持停用。
- **目标已有同邮箱用户**：保留目标用户 ID、密码、管理员/成员角色和停用状态，更新可迁移的姓名、限额、路由和权益配置，不用来源密码替换目标密码。
- **对外 API 密钥**：迁移的是不可逆校验哈希，已持有原密钥的客户端更换站点地址后可继续使用授权模型；无法通过配置包或后台重新查看原密钥。密钥所属管理员仍须在目标站有效。

源站的已用次数不随配置包迁移。全新目标站从零开始计算使用量；已有目标站保留自己的请求记录及计数。迁移了“每天 10 次”的限额，不代表也迁移“今天已经用了 7 次”。

## 套餐与 Stripe 的边界

当前有效的源站套餐权益会转换成目标站的**管理员指定权益**，保留套餐快照与原到期时间；长期权益仍为长期，固定期限不会因导入重新延长。到期后按目标站当前实际订阅或免费配置计算权益。已到期的源站套餐不会重新开通。

导入不会发起支付、取消订阅或转移自动续费。源站原 Stripe 订阅仍独立存在，其续费通知不会自动给目标站延长权益，原客户门户及订单关联也没有迁移。切换实际经营中的付费站点时，应使用完整数据迁移流程，而非依赖配置导入转移订阅。

套餐价格和支付密钥属于配置；若目标站已有 Stripe 订单等支付资产，且来源支付开关或密钥不同，导入保留目标支付开关及两项密钥，在预览说明；免费模型范围仍按来源更新。保留来源支付设置也不等于新域名已配置好 Stripe Webhook，需按 [会员与支付指南](MEMBERSHIP.md) 验证。

## 加密与验证范围

配置迁移仅提供加密导出，使用 scrypt 派生密钥与 AES-256-GCM。源站先解密已保存的渠道/支付凭据，再加密进迁移包；目标站解密后使用自己的主密钥重新保存。源、目标 `master.key` 可以不同。

配置包包含用户密码哈希及服务密钥，妥善保存文件与备份密码，勿提交到代码仓库或 Issue。备份密码丢失无法恢复。网页选择的加密 JSON 文件上限为 44 MiB，解密后的配置内容上限为 32 MiB，版本、字段及引用关系需要通过服务器验证。

本功能的验证使用本地模拟站点和数据库；真实 VPS 切换、Docker 服务连通性、上游调用与 Stripe 收款应在目标环境逐项验收。
